# 听她说话（hervoice）

上游：https://github.com/fishisfish0614/hervoice · MIT · [@noheyischu](https://x.com/noheyischu)

> Based on [hervoice](https://github.com/fishisfish0614/hervoice) by [@noheyischu](https://x.com/noheyischu)

`hervoice.py` `requirements.txt` `README.md` `LICENSE` `.env.example` 是**从上游
原样搬过来的，一个字节没改**（diff 校验过）。接入逻辑全在 `app/listen.py`。

## 它跟 app/voice.py 正好是一对

| | 方向 | 干什么 |
|---|---|---|
| `app/voice.py` | 我 → 她 | ElevenLabs 合成，我说给她听 |
| `app/listen.py` + hervoice | 她 → 我 | Whisper 转写 + librosa 声学特征 + LLM 判语气 |

上游 README 里那句话就是这件事的全部理由：

> 难过的时候，人常常组织不出一句完整的话，但能哼一声、能叹一口气。
> 文字会把这些抹平——「我没事」三个字，打出来和说出来是两回事。

## 怎么用

输入框那个麦克风键（原来点了只弹「语音功能开发中」）。**按住说话，松手发送，
上滑取消。** 松手之后转写会**填进输入框**而不是直接发出去——转写会出错，
让她过一眼再决定。语气跟着这一句一起送给我。

## 三条设计上的硬规矩

**1. 语气不进她那条消息的显示文本。**
她说出口的是那句话，不是那段分析。显示出来就变成「系统在她旁边标注她的情绪」，
那个感觉很差。语气只挂在**用户消息侧**送给模型，跟琴房的 `piano` 字段一个待遇。

**2. 语气也不进 system prompt。** 它每轮都在变，进稳定前缀会把缓存打穿——
`main.py` 里 `ChatBody.piano` 那条注释写的就是这件事。

**3. 语气用完立刻清掉。** 它只属于说出来的那一句，不能粘到下一条打字的消息上。

## 部署

`.env` 里 `HERVOICE_ENABLED=1`，再填 `GROQ_API_KEY`（转写）和 `LLM_API_KEY`
（判语气，上游默认 DeepSeek）。**留 0 的话麦克风键按下去只提示没开启，
其余一切照旧。**

- 🔴 `ffmpeg` 是硬依赖，Dockerfile 里已经装了（把手机录的 webm 转 16k wav）
- 🔴 `librosa`/`numpy` 小窝本来就有（琴房频谱在用）。而且**上游的
  `import librosa` 写在函数里、不在模块顶部**，正好合仓库里那条
  「顶部 import 会把常驻内存永久抬高」的规矩——不会白抬那几十 MB
- 🔴 `HERVOICE_ENABLED=0` 时 entrypoint **根本不起这个进程**，不用就不占
- 🔴 `HERVOICE_DATA` 必须持久卷
- 🔴 **麦克风需要 HTTPS**（或 localhost）。走域名没问题；拿不到权限时前端会
  按协议给出不同的提示，不会让她按半天以为坏了
- 🔴 **`api.groq.com` 写死在上游源码里**（`hervoice.py:57`），没有环境变量。
  跟 ElevenLabs 一个问题：国内服务器连 Groq 未必顺，而且**改不了**。
  真连不上的话只能改上游那一行（那就不是原样搬了），或者在服务器上做 DNS/代理。
  判语气那个 LLM 是可配的（`LLM_BASE_URL`），只有转写这条卡死

## 隐私

音频**默认阅后即焚**（分析完就删，只留文字和语气），`KEEP_AUDIO=1` 才留存。
小窝这边**一个字节都不落盘**——上传是流式转发给 hervoice 的。
录音是她的声音，比书还私密，所以 `/api/listen` 走小窝的登录，
hervoice 自己只 listen `127.0.0.1`。

hervoice 自己那个「按住说话」的网页也能用，它分析完会 POST 到
`/api/listen/hook`，靠 `HERVOICE_HOOK_TOKEN` 两边一致才收；**留空就整条不启用**
（不在公网上开一个谁都能 POST 的口子）。那条路**故意不唤醒我**——从小窝里按
麦克风走的是同步路径，已经把语气带进那一轮了，再唤醒会变成她说一句我回两次。
