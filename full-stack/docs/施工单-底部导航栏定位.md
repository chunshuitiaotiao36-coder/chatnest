# 施工单：底部导航栏（#tabBar）

**报告人**：小朵（iPhone，PWA 加到主屏）
**症状**：`我点一下导航栏就往上窜一截`。导航栏不贴屏幕底，浮在内容下方；
切不同 tab 会跳到不同高度。书房页截图里它在屏幕约 70% 处，下面一大片空白。

**这份单子由 Claude Code（云端）写，执行方在本地。**
🔴 动手前先读 §4「我的环境不可信」。

---

## 1. 根因（查到底了，不是推测）

用 CDP + 静态解析核对过，`#tabBar` 这一整条导航栏**从来没有布局样式**：

| 选择器 | 改之前的全部声明 |
|---|---|
| `#tabBar` | 无（只有浏览器 UA 默认的 `nav{display:block}`） |
| `.tab-item` | `position:relative` ——只有这一条 |
| `.tab-icon` | **无** |
| `.tab-label` | **无** |
| `.tab-badge` | `position:absolute;top:-1px;right:2px;…`（相对内容宽度的 button 算的） |

后果有两层，症状是两层叠出来的：

**第一层 · 横向塌陷。** 五个 `<button>` 是 inline-block，各自按内容宽度排。
393 宽的屏幕上实测它们只占 `0..207`，右边 186px 全是空的。

**第二层 · 纵向会跳。** 整条栏没有 `height`，高度由这一行 inline-block 的基线撑出来。
内容一变（红点显隐、字体加载完、`active` 态换字重）整条栏就变高，
而它当时是 `position:static`、又是 `<body>` 文档流的最后一个元素——
落点完全由前面那些 `.tab-page` 有多高决定：

| 页面 | tab 页高度 | 导航栏落点（视口 852） |
|---|---|---|
| 全部隐藏 | 0 | 0..82 |
| 书房 | 548 | 548..629 |
| 对话列表（曾写死 100dvh） | 852 | 852..934（掉出屏幕） |

「点一下就往上窜一截」就是这张表。以前没暴露，是因为 `#chat`
（`position:fixed;inset:0;z-index:20`）把整个视口盖住了，导航栏藏在它背后。
这一轮把会话列表做成独立 tab、开始频繁切页，才原形毕露。

## 2. 已经做了什么（三层，都在这次 commit 里）

**① 把导航栏当成一个真正的组件写出来**（这是主修）

```css
#tabBar{position:fixed;left:0;right:0;bottom:0;z-index:81;
        display:flex;align-items:stretch;
        background:var(--bg-primary);border-top:1px solid var(--border);
        padding-bottom:env(safe-area-inset-bottom,34px);
        transform:translateY(var(--tabbar-fix,0px))}
body.has-bg-light #tabBar,body.has-bg-dark #tabBar{
        background:var(--glass-panel-strong);border-top-color:var(--glass-line)}
#tabBar .tab-item{flex:1 1 0;height:52px;display:flex;flex-direction:column;
        align-items:center;justify-content:center;gap:4px;…}
#tabBar .tab-icon{width:23px;height:23px}
#tabBar .tab-label{font-size:10px}
#tabBar .tab-badge{top:6px;right:auto;left:calc(50% + 7px)}
```

`flex:1 1 0` 让宽度跟文字内容脱钩（「潮汐」和「Home」占一样宽）；
`height` 写死让红点显隐、字体加载都不再改变整条栏的高度。

**② `position:fixed;bottom:0`**（commit 92f13e7 已做，保留）

z-index 81 是夹出来的，**两边都不能动**：
- `> 80`：压过 `#memoryPanel`（Profile 面板，Home 这个 tab 的内容，`fixed inset:0 z-80`），
  不抬上来她从 Home 切不走；
- `< 82`：低于 `.fsheet`（寄相思 / 朋友圈 / 星图 / 日记四个全屏面板），
  拉开它们时导航栏本来就该被盖住；
- 再往上 900 / 1001 / 1002 是长按菜单，也都该压过导航栏。

**③ 几何兜底**（`syncTabbarHeight()`）

```js
bar.style.setProperty('--tabbar-fix','0px');            // 先归零，否则会一次次叠加
if(cs.position!=='fixed') bar.style.position='fixed';   // 极端兜底
const gap=Math.round(document.documentElement.clientHeight
                     -bar.getBoundingClientRect().bottom);
if(Math.abs(gap)>1) bar.style.setProperty('--tabbar-fix',gap+'px');
```

不管 `position:fixed` 为什么没钉住（祖先 containing block / dvh 与视口不一致 /
iOS 自己的实现），直接量「离屏幕底差多少」，差多少补多少。
**环境正常时 gap 恒为 0，这段等于没执行**——它不改变任何已经正确的行为。

基准用 `documentElement.clientHeight`（layout viewport）而不是 `visualViewport.height`：
后者在键盘弹起时会缩，会把导航栏拽到键盘上面去。

调用时机：`switchTab()` 内、`resize`、`orientationchange`（延时 300ms）、
`pageshow`、`visualViewport.resize`。

## 3. 真机诊断面板（新增，这是这次最有用的东西）

**长按底部导航栏任意位置 1.2 秒**，弹出一个黑底面板，点任意处关闭，什么都不留。
里面有：

- `BUILD` 版本串 —— **一眼看出手机上跑的到底是不是最新那版**，
  还是 PWA 缓存里的旧页面。这一行优先看。
- `innerHeight` / `docEl.clientHeight` / `visualViewport.height` / `screen.height`
- `safe-area top/bot` 实测值（用离屏探针量的，`env()` 只能在 CSS 里求值）
- `#tabBar` 的 computed position、rect、**离屏幕底 gap**、`--tabbar-h`、`--tabbar-fix`
- 祖先链逐级的 transform / filter / backdrop-filter / perspective / will-change / contain
- 当前 tab、`body.className`

长按不会误切 tab（捕获阶段拦了随后那次 click），手指挪动超过 10px 视为划动、取消。

## 4. 🔴 我的环境不可信

08-19 这一天，云端 Chromium 至少四次给出与真机相反的结论：

1. `env(safe-area-inset-top)` 在 Chromium 里解析为 **0**，回退值让预览看着正常，
   真机上是 59px，整块内容顶进状态栏。
2. 所有 `.tab-page` 在云端都被遮住（`elementFromPoint` 永远命中别的层），
   真机上书房 / 琴房 / Home 都正常显示。我据此给列表页加 `position:fixed;z-index:21`、
   把 tabBar 抬到 z-22，**把原本没坏的东西改坏了**（导航栏跑到屏幕顶部）。
3. 拉三个历史版本对比，**三个在云端都是「坏」的**，包括她明确说能正常用的那一版。
4. 只要给 `<body>` 加上 `.chat-ready`，侧栏 `#drawer`（宽 322px）就盖住所有 tab 页——
   真机上不会。

**结论：这个环境测不出 `#chat` / `#drawer` / `.tab-page` / `#tabBar` 之间真实的
遮盖与定位关系。** 凡是遇到「明明该坏却没坏」或者反过来，先假设是环境差异，
不要照着现象改代码。§1 那张表和 §2 的宽度实测是静态量出来的，不受此限。

## 5. 如果部署之后仍然不对

**先排除缓存（成本最低）**：iOS 的 PWA 在「添加到主屏幕」那一刻会把页面复制走，
之后不保证跟着服务端更新。

1. 确认 Coolify 部署到了含本单改动的 commit；
2. 长按导航栏看 `BUILD` 那一行对不对——不对就是缓存；
3. 让她**删掉主屏图标重新添加**，再看一次；
4. 或先用 Safari 直接开站点地址对比：Safari 里对、PWA 里错 = 缓存问题。

她给的教程里写的是同一条：
`https://claudepuppy.xyz/docs/pwa_statusbar_tutorial.html`
> Reinstall after changes: Delete the home screen icon and re-add it;
> Safari preview doesn't reflect true PWA behavior.

**BUILD 对得上、重装过、还是不对**，就看诊断面板里这两项：

- **祖先链有 ⚠**（`#tabBar` 自己那行带 backdrop-filter 是正常的，看 BODY / HTML 那两行）：
  祖先创建了 containing block，`fixed` 相对它而不是视口。去掉那个祖先的
  `transform` / `filter` / `will-change`，或把 `#tabBar` 挪出去。
- **祖先链干净但 gap ≠ 0**：`--tabbar-fix` 应该已经把它补回去了。如果 `--tabbar-fix`
  显示的值不等于 gap，说明 `syncTabbarHeight()` 没被调到，查调用点。
- **位置对但点不动**：层叠问题，回 §2 那个 z-index 夹缝重算，
  用 `document.elementFromPoint` 找出到底是谁挡着。

## 6. 🔴 不许动的地方（都有 commit 记录）

1. **`index.html` 第 6–23 行**（viewport / apple-mobile-web-app-* 那几个 meta）。
   不许加 `theme-color`，不许加 `<link rel="manifest">`——加任何一个，
   iOS 的沉浸式状态栏当场失效，退回实心状态栏。
2. **不要给 `.tab-page` 或 `#tabChats` 加 `position:fixed`**。试过，导航栏跑屏幕顶上。
3. **不要动 `.sheet` 这个类名**。项目里已有一套底部弹出层用这个名字
   （思考面板、模型选择器、琴房）。新面板用的是 `.fsheet`，别合并。
4. **`claude-trail-logo` 那个精灵动画不要替换成头像**，那是刻意保留的。
5. **改字体里那句诗要重新做子集**。霞鹜文楷是按 13 个字子集后内嵌的
   （19MB → 3700 字节），直接改字会掉回系统字体。花体同理，只含 `c/h/a/t` 四个字母。
6. **改了导航栏样式要同步更新 `BUILD` 常量**，否则诊断面板会撒谎。
