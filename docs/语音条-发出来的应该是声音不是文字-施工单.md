# 语音条：发出来的应该是声音，不是文字 —— 施工单

> 2026-09-02 晚。收音已经修好了（见下「已完成」），但**方向本身是错的**：
> 她要的是把**声音**发出去，转写和情绪分析退到后台只给模型看。
> 这一份是功能改动，不是 bug 修复。

## 她的原话

> 部署了能收音了但是直接给我转文字了，**我要把声音发出来啊**，
> 转文字和分析情绪不是另外接的两个小模型该做的事吗

她的理解是对的：hervoice 干的就是「转写 + 声学特征 + 判情感」。
错在前端把转写结果当成了「她要发的内容」，而不是「给模型的旁注」。

## 已完成（`9c637ef`，真机确认收音正常）

按住说话之前完全没反应，三处已修：

1. `_rec.start()` → `_rec.start(500)` —— 不传 timeslice 时只在 `stop()` 补一次
   `dataavailable`，iOS 上那一次有时排在 `onstop` **后面**，`recFinish` 拿到空数组。
   **这条是根因，已验证。**
2. 两个静默 `return`（chunks 为空 / blob<1200）改成 toast 出声。
3. 上传文件名跟 `blob.type` 走（iOS 录出来是 `audio/mp4`，原来硬写 `.webm`）。

## 现状 vs 目标

| | 现在 | 她要的 |
|---|---|---|
| 松手之后 | 转写文字**填进输入框**，等她过目再发 | **直接发出去，消息就是一条语音条** |
| 消息里显示 | 一段文字 | 语音条（能播她自己的声音） |
| 转写文本 | 就是消息本体 | 退到后台，作为模型看到的内容 |
| 情绪/hint | 已经是旁注（`listen.tone_block`，只进用户消息侧） | 不变 |

现在这个行为是当初刻意写的，注释在 `index.html` 的 `recFinish()` 里：

```
🔴 填进输入框而不是直接发出去：转写会出错，让她过一眼再决定。
```

⇒ **改之前先确认她是否接受「转写错了也直接发出去」**。折中方案见下面「开放问题」。

## 🔴 必须先拍板的一件事：音频要落盘

`listen.py:19` 写死了当初的决定：

```
🔴 音频不落小窝的盘。整个上传是流式转发过去的，我们这边一个字节都不存；
   留不留音频是 hervoice 那边 KEEP_AUDIO 的事，默认阅后即焚。
```

**要发语音条就必须存音频**——否则退出对话再进来那条就没得播（`voice_say` 当年
踩过一模一样的坑，她原话「这个语音条怎么还是阅后即焚样式的」）。

这跟「录音是她的声音，比书还私密」那条原则冲突。**这是她的决定，不是实现细节，
动手前先问她。** 若她同意，落盘路径建议与上传隔开，单独一个目录便于整体清理。

## 不能直接复用 assistant 那套语音条

`voice_say` 存的是**文本**，播放时现场 TTS 合成（`/api/voice/*`）。
用户这边要存的是**原始录音文件**，两者只有前端外观可以借鉴，数据通路完全不同。

## 要改的地方

1. **存音频**：新模块或扩 `uploads.py`。路径如
   `AGENT_APP_ROOT/voice-notes/<conv_id>/<时间戳>_<hex>.<ext>`，
   沿用 `_inside()` 那套越权校验；会话删除时一并清理
   （参考 `remove_conversation_uploads`）。
2. **`listen.py`**：现在是纯流式转发。改成「边存边转发」，或先落盘再以文件转发。
   注意 90s 超时与 `content-length` 透传别破坏。
3. **`store.py`**：`messages` 加一列（如 `voice_note TEXT NOT NULL DEFAULT ''`）存
   音频相对路径 + 迁移。🔴 **加列时三处都要改**：列名、占位符、值——
   `restore_branch` 那条 INSERT 就是只改了列名，导致每次重试必炸
   （见 `test_branch_restore.py` 的由来）。加完跑那个测试。
4. **播放路由**：`/api/voice-note/{conv_id}/{name}`，`require_auth` + 路径校验。
5. **前端 `recFinish()`**：不再 `input.value += d.text`，改为直接发送——
   消息本体用转写文本（给模型），同时带上音频引用（给她看/听）。
6. **前端渲染**：用户侧语音条 + **历史渲染也要挂**（`_renderMessagesIntoFragment`
   里现在只处理 `m.voice_say` 和 `m.mood`），否则又是「阅后即焚样式」。
