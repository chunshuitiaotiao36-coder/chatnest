# 导航栏底部 59px 空带 —— 交接单

> **2026-09-02 20:00 结论已定性，见下面第一节。改 CSS 修不好这个 bug。**

## 真因（已用真机实验确证）

**iOS PWA 启动时 `innerHeight` 少报一个 `safe-area-inset-top`（她机器上 793 而非 852）。
任意一次真实触摸交互会让它归位到 852。塌陷期间 `position:fixed;bottom:0` 钉在 793，
屏幕底部 793..852 成为页面画不到的死区。**

实验：`/vptest.html`（一张不含小窝任何代码的空白页）从主屏图标打开，
同一次会话内前后两张截图：

| | 刚打开 | 用手扒拉一下之后 |
|---|---|---|
| `screen.height` | 852 | 852 |
| **`innerHeight`** | **793** | **852** ✅ |
| `visualViewport.h` | 793 | 852 |
| `scrollHeight` | 793 | 852 |
| `clientHeight` | 793 | 793（**始终不变**）|
| `safe-area top/bot` | 59 / 34 | 59 / 34 |
| 红条(`fixed;bottom:0`)底边 | 793 | 892（页面被拖了 40，fixed 跟着跑）|

空白页也复现 ⇒ **与小窝的 HTML / CSS / Service Worker 完全无关。**

### 这解释了全部历史疑点

- **黑框框 08-20 的真机表是 `innerHeight 852 / vh 793`** —— 那正是「归位后」的形态。
  他测之前必然已经操作过 app，所以前九轮从没见过塌陷态，`bdbffd6` 才会判定
  「布局视口从头到尾没缩过」。那个判定在**归位后**成立，在**刚启动时**不成立。
- 我 09-02 一整天改 CSS 毫无效果 —— 塌的是视口，不是样式。
- 诊断面板报「✓ 视口也是满的」是假阳性：`shrunk=852-793=59`，旧阈值 `>60`，差 1px 漏判。
  （已修：塌陷判定提到几何之前，容差降到 8）

### ⚠️ 纯 JS「踢一脚」全部无效（已实测）

测试页上做了 5 个按钮，真机逐个点过，`innerHeight` **一个都没变**：

| | 手法 | 结果 |
|---|---|---|
| A | `scrollTo(0,1)` → `scrollTo(0,0)` | ✗ |
| B | `body.style.minHeight` 撑高 1px 再收回（强制 reflow） | ✗ |
| C | `documentElement` `display:none` → 复原 | ✗ |
| D | 临时 `<input>` `focus()` 再 `blur()` | ✗ |
| E | `dispatchEvent(new Event('resize'))` | ✗ |

⇒ **只有真实触摸能让它归位，代码模拟不了。** 别再往这个方向投入。

### 因此可走的方向（均未验证）

1. **别用 `fixed; bottom:0` 定位导航栏。** 注意归位后红条底边跑到 892
   （页面被拖 40px，fixed 跟着滚），说明这条路在两种状态下都不稳。
2. 先测准 `100dvh` 在**塌陷态**下等于几（测试页的绿框就是 `100dvh`，
   把它的 `getBoundingClientRect()` 打出来即可）。若它恒等于 852，
   则 `top: calc(100dvh - var(--tabbar-space))` 可用。
3. 或者监听 `resize`，在 `innerHeight` 归位的那一刻重新校准导航栏位置
   —— 但用户不触摸就永远不归位，首屏依旧是坏的。
4. 或者接受 793，用别的手段填掉 793..852（注意：那块区域页面画不进去，
   只能靠 canvas 背景色即 `html`/`body` 的 background 去盖）。

### 复现与验证工具

`/vptest.html`（路由在 `main.py` 的 `vptest()`，文件在 `static/vptest.html`）。
**必须从主屏图标打开**（Safari 里有工具栏几何干扰，测不出来）。
页面会打印全部视口指标并自行判定；5 个「踢一脚」按钮点了会显示
`innerHeight` 前后值，归位则按钮变绿。定性完可连同路由一起删。

## 症状

所有带导航栏的页面，屏幕最底下有一条 **59px 的空带**，颜色跟页面和导航栏都不一样。
深色纯底的页面（潮汐）最扎眼；壁纸页（Home）能糊过去，但缝一样在。

- 设备：iPhone 15 Pro Max，PWA 独立模式（已添加到主屏）
- 截图 1179×2556 物理 = **CSS 393×852**
- 空带位置：**CSS 793 .. 852**，颜色 `(243,243,241)`

## 已量实的核心事实

**同一台机器、同一个 app 里，两套定位方式给出不同的底边：**

| 元素 | 定位方式 | 底边落在 |
|---|---|---|
| `#chat` / `#tabChats` | `height:100dvh` | **852** ✅ 贴底 |
| `#tabBar` | `position:fixed; bottom:0` | **793** ❌ 差 59 |
| `.tab-page` | `position:fixed; inset:0` | **793** ❌ 差 59 |

### 🔴 这是回归，不是 iOS 固有行为

我一开始推测「iOS 在 black-translucent 下把固定定位包含块做成屏幕高−状态栏高」，
**这个推测是错的**，被 `bdbffd6` 的真机诊断表（08-20 14:11，同一台机器）推翻：

```
#tabBar top..bot   422 .. 852        screen.height 852
vh 全程 793 = 852 - 59（59 是 safe-area-top）
innerHeight 852    visualViewport.h 852    focus 全程 BODY
--tabbar-h         396px   ← 当时的 bug：正反馈把导航栏撑高到 430
```

**`#tabBar` 的底边当时就在 852 = 屏幕底。**`position:fixed; bottom:0` 在这台机器上
**本来到得了 852**。`clientHeight` 是 793 不假（不含刘海），但固定定位包含块是 852。

⇒ 现在它只到 793，是**有东西把固定定位包含块从 852 改成了 793**，要找的是这个。
   拿 `100dvh` 去绕开只是把症状盖住，会把真正的回归留在那儿。

**相关历史**：`d1ca682` 修过一次「布局视口被撑高」——`#modelSheet` 的
`.sheet`(fixed) 被后加载的 `.glass`(relative) 压过，一个 `height:95dvh` 的块留在
正常流里又被 `translateY(100%)` 推下去，`html.scrollHeight` 变成 1619。
修完 scrollHeight 回到 852。**同类机制（某个元素改变了文档/视口的几何）值得优先查。**

### 证据：是视口缩短，不是整页平移

两张聊天页截图对齐量（右上角橙色 `+` 按钮做基准）：

| | 橙色 + 按钮中心 | 输入框特征带 |
|---|---|---|
| 09:15（好） | css **86.8** | 815.3 |
| 14:22（坏） | css **86.7** | 756.3 |
| 差 | **0.1px** 顶部钉死 | **59.0px** |

## 🔴 09-02 19:09 真机诊断表 —— 真因已定性：布局视口塌了

小朵长按导航栏拍的表（同机 iPhone 15 Pro Max）：

```
BUILD  2026-08-20 · 头像裁切收尾     standalone  true
innerHeight          793      ← 08-20 那次是 852
docEl.clientHeight   793
visualViewport.h     793
screen.height        852      dpr 3
safe-area  top/bot   59 / 34  ← 非 0，说明 viewport-fit=cover **是生效的**
屏幕高-布局视口高      59
当前焦点             BODY     ← 不是键盘吃的
#tabBar  position fixed   top..bot 703..793   高 90   --tabbar-h 56px
祖先链  NAV#tabBar / BODY pos=static / HTML pos=static   ← 无 transform 祖先
```

**布局视口 = 793，而且画在屏幕的 0..793**。底部 793..852 是页面**根本画不到**的死区。

旁证：诊断面板自己是 `position:fixed; inset:0`，量它的截图——
面板底色 `(10,10,12)` 到 **css 792.7** 为止，793..851.7 是 `(25,25,25)`。
**连全屏覆盖的面板都够不到 793 以下。**

⇒ **这不是 CSS 问题。** `#tabBar` / `.tab-page` / `--tabbar-h` 全部健康
（高 90、position fixed、无 inline、无 transform 祖先）。改任何 CSS 都盖不住那 59px，
因为那块区域页面画不进去。我 09-02 上午改一天 CSS 毫无效果，原因就在这。

### 面板当时报了绿灯，是假阳性（已在同一提交里修掉）

```js
const shrunk = screen.height - innerHeight;   // 852 - 793 = 59
else if (shrunk > 60)  v = '△ 布局视口比屏幕矮…'   // 59 不满足，漏过去
else                   v = '✓ 导航栏钉在底部，视口也是满的'
```

阈值 60 是当初为躲开「刘海 59 的坐标系假警报」设的，这次真塌了 59，**差 1px 漏判**。
`gap=0` 同样是假的——它拿 `innerHeight` 当基准，而 `innerHeight` 自己塌了，
gap=0 只说明「贴到了布局视口的底」。
现已改成：视口塌陷**排在导航栏几何之前**判，容差降到 8px。

### 下一步该查什么

`viewport-fit=cover` 生效、meta 从 08-20 至今一字未改、无 theme-color / 无 manifest、
焦点是 BODY、祖先链无 transform —— 代码侧的常见嫌疑**全部排除**。
`innerHeight` 从 852 变成 793 是**环境状态**，优先按这个顺序试（都不用改代码）：

1. **完全杀掉 app**（多任务上划掉）再打开 —— 排掉「启动/后台恢复时视口协商卡在错误尺寸」
2. **删掉主屏图标，重新「添加到主屏」** —— iOS 在安装时固化 PWA 显示配置，重装会重新协商
3. 若 1、2 都无效：确认手机 iOS 版本在 08-20 之后是否更新过（新版可能改了 PWA 视口行为）

**只有以上都排除，才轮到改代码。** 那时再考虑用 `100dvh` 兜底（见下文），
但要清楚那只是把死区让开，不是让页面画到 852。

## 修法

### 第一优先：先找回归（因为 fixed 本来能到 852）

按 `d1ca682` 的路子查「谁改变了视口几何」：

```js
// 真机 / Safari 远程调试里跑
document.scrollingElement.scrollHeight   // 应 == clientHeight，被撑高就是有元素跑出流
innerHeight, document.documentElement.clientHeight, visualViewport.height
$('tabBar').getBoundingClientRect()      // 底边应为 852
```

重点怀疑：留在正常流里、又被 transform 推走的大块元素（`.sheet` / `.fsheet` /
`.letter-overlay` / `#modelSheet` 这类），以及**双写陷阱**——同一个选择器在
`index.html` 内联 `<style>` 和 `design-system.css` 里各写一份，后加载的赢。
黑框框栽过两次（`bdbffd6`、`d1ca682`），两次都是「全文件查过」只查了 index.html。

### 兜底（仅在确认不是回归、就是 iOS 行为变化时才用）

```css
#tabBar {
  top: calc(100dvh - var(--tabbar-space));
  bottom: auto;
}
.tab-page {
  height: 100dvh;
  bottom: auto;   /* 让 top:0 + height 说了算，跟 #chat/#tabChats 一致 */
}
```

几何验算（`--tabbar-space` = 56 + 34 = 90）：
- `top = 852 − 90 = 762` → 导航栏 **762..852**，贴底，高度不变，图标不跑位
- `.tab-page` 0..852，其 `padding-bottom:90px` 内容止于 **762** = 导航栏顶边，严丝合缝

**风险点，必须真机确认：**
1. `100dvh` 在键盘弹起时会不会变（viewport meta 是 `interactive-widget=resizes-visual`，理论上不变）
2. 转屏 / 分屏下 `100dvh` 是否仍等于视口高
3. `body.keyboard-open #tabBar` 那条 translate 收起逻辑不受影响（改的是 `top`，不是 `transform`）
