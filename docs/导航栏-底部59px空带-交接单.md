# 导航栏底部 59px 空带 —— 交接单

> 2026-09-02。小朵已经为这个 bug 耗掉一上午，我（web 端）修了 4 次全部失败。
> 这份单子把**量到的事实**和**已证伪的路**写死，接手的人不用再从头猜。

## 症状

所有带导航栏的页面，屏幕最底下有一条 **59px 的空带**，颜色跟页面和导航栏都不一样。
深色纯底的页面（潮汐）最扎眼；壁纸页（Home）能糊过去，但缝一样在。

- 设备：iPhone 15 Pro Max，PWA 独立模式（已添加到主屏）
- 截图 1179×2556 物理 = **CSS 393×852**
- 空带位置：**CSS 793 .. 852**，颜色 `(243,243,241)`

## 已量实的核心事实

**同一台机器、同一个 app 里，两套定位方式给出不同的底边：**

| 元素 | 定位方式 | 底边落在 |
|---|---|---|
| `#chat` / `#tabChats` | `height:100dvh` | **852** ✅ 贴底 |
| `#tabBar` | `position:fixed; bottom:0` | **793** ❌ 差 59 |
| `.tab-page` | `position:fixed; inset:0` | **793** ❌ 差 59 |

### 🔴 这是回归，不是 iOS 固有行为

我一开始推测「iOS 在 black-translucent 下把固定定位包含块做成屏幕高−状态栏高」，
**这个推测是错的**，被 `bdbffd6` 的真机诊断表（08-20 14:11，同一台机器）推翻：

```
#tabBar top..bot   422 .. 852        screen.height 852
vh 全程 793 = 852 - 59（59 是 safe-area-top）
innerHeight 852    visualViewport.h 852    focus 全程 BODY
--tabbar-h         396px   ← 当时的 bug：正反馈把导航栏撑高到 430
```

**`#tabBar` 的底边当时就在 852 = 屏幕底。**`position:fixed; bottom:0` 在这台机器上
**本来到得了 852**。`clientHeight` 是 793 不假（不含刘海），但固定定位包含块是 852。

⇒ 现在它只到 793，是**有东西把固定定位包含块从 852 改成了 793**，要找的是这个。
   拿 `100dvh` 去绕开只是把症状盖住，会把真正的回归留在那儿。

**相关历史**：`d1ca682` 修过一次「布局视口被撑高」——`#modelSheet` 的
`.sheet`(fixed) 被后加载的 `.glass`(relative) 压过，一个 `height:95dvh` 的块留在
正常流里又被 `translateY(100%)` 推下去，`html.scrollHeight` 变成 1619。
修完 scrollHeight 回到 852。**同类机制（某个元素改变了文档/视口的几何）值得优先查。**

### 证据：是视口缩短，不是整页平移

两张聊天页截图对齐量（右上角橙色 `+` 按钮做基准）：

| | 橙色 + 按钮中心 | 输入框特征带 |
|---|---|---|
| 09:15（好） | css **86.8** | 815.3 |
| 14:22（坏） | css **86.7** | 756.3 |
| 差 | **0.1px** 顶部钉死 | **59.0px** |

## 已知好的版本

**`d1ca682`**（09-02 00:38 UTC = 08:38 北京）。
09:15 北京的真机截图证实：聊天页输入框贴底 852，底部只有 3.3px 的内容边缘，**无缝**。

`#chat` 贴底，**没有**证明导航栏当时贴底。导航栏的缝在 `d1ca682` 可能就存在。）

**另外两条历史坑（更早的会话踩过）：**
- 拿 `documentElement.clientHeight` 当基准算「离屏底几 px」——它恒等于 793，算出来永远是 0，
  焊死逻辑一次都不会动手。这是 08-20 误判「位置从来没错过」的根源。
- 给 `#tabBar` 加 `transform`（`e2b2ccc` 的 `--tabbar-fix`）——会把 fixed 元素踢出视口
  坐标系，导航栏飘到屏幕中间。`translateX(--drawer-x)` 是侧栏联动，**必须保留**，别写 `transform:none`。

## 修法

### 第一优先：先找回归（因为 fixed 本来能到 852）

按 `d1ca682` 的路子查「谁改变了视口几何」：

```js
// 真机 / Safari 远程调试里跑
document.scrollingElement.scrollHeight   // 应 == clientHeight，被撑高就是有元素跑出流
innerHeight, document.documentElement.clientHeight, visualViewport.height
$('tabBar').getBoundingClientRect()      // 底边应为 852
```

重点怀疑：留在正常流里、又被 transform 推走的大块元素（`.sheet` / `.fsheet` /
`.letter-overlay` / `#modelSheet` 这类），以及**双写陷阱**——同一个选择器在
`index.html` 内联 `<style>` 和 `design-system.css` 里各写一份，后加载的赢。
黑框框栽过两次（`bdbffd6`、`d1ca682`），两次都是「全文件查过」只查了 index.html。

### 兜底（仅在确认不是回归、就是 iOS 行为变化时才用）

```css
#tabBar {
  top: calc(100dvh - var(--tabbar-space));
  bottom: auto;
}
.tab-page {
  height: 100dvh;
  bottom: auto;   /* 让 top:0 + height 说了算，跟 #chat/#tabChats 一致 */
}
```

几何验算（`--tabbar-space` = 56 + 34 = 90）：
- `top = 852 − 90 = 762` → 导航栏 **762..852**，贴底，高度不变，图标不跑位
- `.tab-page` 0..852，其 `padding-bottom:90px` 内容止于 **762** = 导航栏顶边，严丝合缝

**风险点，必须真机确认：**
1. `100dvh` 在键盘弹起时会不会变（viewport meta 是 `interactive-widget=resizes-visual`，理论上不变）
2. 转屏 / 分屏下 `100dvh` 是否仍等于视口高
3. `body.keyboard-open #tabBar` 那条 translate 收起逻辑不受影响（改的是 `top`，不是 `transform`）

## 真机诊断面板（黑框框留的，优先用它）

**长按底部导航栏 1.2 秒** → 震动一下 → 黑底诊断表 → 截图 → 点任意处关闭。

它直接给出：`BUILD`（**线上版本，先看这行**）、`standalone`、`innerHeight`、
`docEl.clientHeight`、`visualViewport.h`、`screen.height`、`safe-area top/bot`、
`屏幕高-布局视口高`、`#tabBar` 的 position/display 和实际 top..bot、切 tab 记录。

代码在 `index.html` 的 `_tbDiag()` / `openTabbarDiag()` / `bindTabbarDiag()`。
**改完之后记得把 `BUILD` 常量更新**（约 8263 行），否则分不清手机上是不是新版本。

## 怎么验证（截图量法，比肉眼靠谱）

改完让小朵截图，跑这个：

```python
from PIL import Image
im = Image.open('截图.png').convert('RGB')
w, h = im.size
print('CSS', w/3, h/3)          # 应为 393 x 852
x, prev, top = 20, im.getpixel((20, h-1)), h-1
for y in range(h-2, h-260, -1):  # 左边缘往上扫，避开卡片内容
    c = im.getpixel((x, y))
    if max(abs(a-b) for a, b in zip(c, prev)) > 3:
        print(f'底部色带 css {(y+1)/3:.1f}..851.7  高 {(top-y)/3:.1f}px  {prev}')
        break
```

- **修好了**：底部色带高度 < 5px（只有内容边缘）
- **没修好**：底部色带 ≈ 59px，颜色 `(243,243,241)`

需要逐像素对齐两张图时，用右上角橙色 `+` 按钮当基准（聊天页）：
顶部对齐说明是视口缩短，顶部也偏移说明是整页平移。
